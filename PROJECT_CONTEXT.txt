1. PROJECT PURPOSE
Photo Group Portal is a full-stack platform for photographers to host event media.
Photographers create isolated rooms and upload bulk photos. Face detection and
embeddings process photos asynchronously. Event attendees scan a room QR code,
initiate a WhatsApp selfie workflow, and receive a secure expiring gallery link
containing only their matched photographs.

6. DATABASE SCHEMA SUMMARY
- `system_health_logs`: id (SERIAL PK), status (VARCHAR), checked_at (TIMESTAMPTZ), details (TEXT).
- Primary engine target: PostgreSQL (`photo_group_portal`).
- Automatic local dev fallback: SQLite (`photo_group_portal_fallback.db`).

7. IMPORTANT BACKEND MODULES
- `backend/app/main.py`: Entry point configuring FastAPI, CORS middleware, API v1 routes.
- `backend/app/core/config.py`: Centralized settings reading env variables with defaults.
- `backend/app/core/database.py`: SQLAlchemy sessionmaker, `get_db` dependency, and health ping function `check_database_connection()`.
- `backend/app/api/health.py`: Route handler for `/api/v1/health`.

8. IMPORTANT FRONTEND COMPONENTS

20. KEY FUNCTIONS & RESPONSIBILITIES
- `check_database_connection()`: Tests SQL connectivity and automatically toggles SQLite fallback if PostgreSQL is unreachable.
- `get_health()`: Assembles system and database diagnostics for `/api/v1/health`.
- `fetchHealth()` (React): Client-side fetcher retrieving backend status via proxy or direct URI.

21. DATA FLOW (DAY 1)
User loads React UI -> React issues GET request to `/api/v1/health` -> FastAPI backend checks SQL database via SQLAlchemy ping -> Backend returns status JSON -> React UI renders connection badges and metrics.

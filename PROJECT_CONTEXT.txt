PHOTO GROUP PORTAL — PROJECT CONTEXT & HANDOFF DOCUMENT

1. PROJECT PURPOSE
Photo Group Portal is a full-stack platform for photographers to host event media.
Photographers create isolated rooms and upload bulk photos. Face detection and
embeddings process photos asynchronously. Event attendees scan a room QR code,
initiate a WhatsApp selfie workflow, and receive a secure expiring gallery link
containing only their matched photographs.

6. DATABASE SCHEMA SUMMARY
- `system_health_logs`: id (SERIAL PK), status (VARCHAR), checked_at (TIMESTAMPTZ), details (TEXT).
- Primary engine target: PostgreSQL (`photo_group_portal`).
- Automatic local dev fallback: SQLite (`photo_group_portal_fallback.db`).

7. IMPORTANT BACKEND MODULES
- `backend/app/main.py`: Main FastAPI app mounting `/api` router, CORS middleware, and root endpoint.
- `backend/app/core/config.py`: Configuration settings reading environment variables.
- `backend/app/core/database.py`: SQLAlchemy sessionmaker, `get_db` dependency, and connection health checker.
- `backend/app/api/health.py`: Route handlers for `GET /api/health` and `GET /api/v1/health`.

8. IMPORTANT FRONTEND MODULES & COMPONENTS
- `frontend/src/api/api.js`: Central API client module reading `VITE_API_URL` with network error isolation and timeouts.
- `frontend/src/pages/HomePage.jsx`: Main dashboard page fetching and rendering backend connection status ("Connected" / "Disconnected").
- `frontend/src/components/Header.jsx`: Application header navbar.
- `frontend/src/components/Footer.jsx`: Application footer.
- `frontend/src/components/StatusBadge.jsx`: Reusable status badge element.

9. API ENDPOINTS (CURRENTLY IMPLEMENTED)
- `GET /`: API welcome message and documentation links.
- `GET /api/health`: Basic status response `{"status": "ok", "service": "Photo Group Portal API"}`.
- `GET /api/v1/health`: Detailed system health status, version, timestamp, environment, and DB connection state.

21. DATA FLOW (DAY 2)

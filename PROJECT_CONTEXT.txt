1. PROJECT PURPOSE
Photo Group Portal is a full-stack platform for photographers to host event media.
Photographers create isolated rooms and upload bulk photos. Face detection and
embeddings process photos asynchronously. Event attendees scan a room QR code,
initiate a WhatsApp selfie workflow, and receive a secure expiring gallery link
containing only their matched photographs.

9. API ENDPOINTS (CURRENTLY IMPLEMENTED)
- `GET /`: Root API welcome message.
- `GET /api/health`: Liveness probe `{"status": "ok", "service": "Photo Group Portal API"}`.
- `GET /api/health/db`: Dedicated DB status `{"status": "ok", "database": "connected"}`.
- `GET /api/health/system`: System status `{"status": "ok", "service": "...", "environment": "development"}`.
- `GET /api/v1/health`: Detailed system metrics.
- `POST /api/v1/auth/login`: OAuth2 login endpoint returning JWT access token.
- `POST /api/v1/users/`: Registration endpoint for creating new users (default role: 'user').
- `GET /api/v1/users/me`: Protected route returning authenticated user profile.

20. KEY FUNCTIONS & RESPONSIBILITIES
- `verify_password()` & `get_password_hash()`: Direct `bcrypt` password verification and hashing.
- `create_access_token()`: Signs JWT access tokens with subject `sub` and expiration.
- `get_current_user()`: Validates OAuth2 bearer tokens and returns DB `User` object.
- `crud_user.authenticate()`: Verifies email & password credentials against database.

21. DATA FLOW (DAY 5)
User submits credentials to `POST /api/v1/auth/login` -> `crud_user.authenticate()` checks email & bcrypt password hash -> Backend creates JWT access token -> Client sends token in header `Authorization: Bearer <token>` to `GET /api/v1/users/me` -> `get_current_user()` decodes token and returns user profile.
